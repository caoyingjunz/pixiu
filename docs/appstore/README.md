# 应用商店使用指南

> 最后更新：2026-10-27　|　维护：平台组

本文面向应用商店使用者，说明如何从 Pixiu 官方 Chart 仓库获取官方 Chart，导入应用商店后安装到目标集群，并对已安装应用进行升级、回滚与卸载。Chart 的上架与打包规范见文末「备注」。

## 适用范围

- 使用 Helm Chart 在 pixiu 管理的 Kubernetes 集群中部署应用。
- 通过页面完成应用的上架、安装、升级、回滚、卸载，无需登录目标集群手工执行 `helm`。

## 前置条件

- pixiu 服务已正常启动，且已纳管至少一个可用的 Kubernetes 集群。
- 当前账号具备应用商店的访问权限；「上架应用」仅 root/admin 可见。
- 安装到指定命名空间时，普通用户仅能安装到属于自己的命名空间，超出范围会在提交时被拒绝。

## 一、获取官方 Chart

官方 Chart 仓库地址：https://github.com/pixiu-io/pixiu-chart-repo ，所有打包产物位于 `charts/` 目录。

获取方式二选一：

- 浏览器打开仓库 `charts` 目录，点击对应的 `.tgz` 下载。
- 克隆仓库后使用本地产物：

```bash
git clone https://github.com/pixiu-io/pixiu-chart-repo.git
ls pixiu-chart-repo/charts/*.tgz
```

## 二、导入 Chart 到应用商店

应用商店入口：左侧菜单「应用商店」（路由 `/appstore`），包含「应用市场」与「已安装应用」两个 Tab。

在「应用市场」中导入：

1. 点击右上角「上架应用」（仅 root/admin 可见）。
2. 选择「分类」（可选）：可观测性、网络、安全、数据库、存储、CI/CD、镜像仓库、服务网格。
3. 拖入或选择 Helm Chart 打包产物（`.tgz`）。
4. 点击「确定」上传。

上传约束：

- 单次仅上传一个文件；单包大小上限由 `appstore.max_upload_mb` 控制，默认 32MB，超限返回 413。
- 同名同版本已存在返回 409；包内容 sha256 与历史版本相同也返回 409（只改版本号不算新包）。
- `library` 类型 Chart 不可安装，上传会被拒绝（400）。

导入成功后，Chart 会出现在「应用市场」中，可点击卡片查看详情。

## 三、安装应用

在「应用市场」点击卡片查看详情或直接点击「安装」，在「安装 Chart」弹窗中填写：

- **目标集群**：选择要部署到的集群。
- **命名空间**：填写或选择命名空间；普通用户仅可安装到属于自己的命名空间。
- **Release 名称**：仅允许小写字母、数字、中划线，长度不超过 53 字符。
- **Chart 版本**：选择要部署的版本。
- **配置**：YAML 编辑器，可点击「默认值」载入平台默认配置，点击「清空」重置。

点击「确定」提交后，后台异步执行安装。安装过程会校验对目标集群与命名空间的权限。

配置值的合并优先级为：**用户在安装表单填写的值 > 平台默认配置 > Chart 内置 values.yaml**；数组合并为整体替换。

## 四、管理已安装应用

切换到「已安装应用」Tab：

- 可按集群筛选，按应用或 Release 名称搜索。
- 行操作包含：`日志`、`升级`，「更多」菜单中提供 `查看配置`、`回滚`、失败时的 `重试` 以及 `卸载`。
- **升级**：选择目标版本并修改配置后提交。升级的合并优先级为：**本次请求值 > 当前 release 的 values > 平台默认配置**。
- **卸载**：删除该 Release 及其部署的命名空间级资源。

## 验证方式

- 导入后：在「应用市场」中能看到对应 Chart，且版本与所上传包一致。
- 安装后：在「已安装应用」中该 Release 状态正常；点击 `日志` 可查看安装过程输出。
- 部署结果：到目标集群的对应命名空间中确认工作负载与 Pod 已创建（具体资源视 Chart 而定）。
- 升级/回滚后：`查看配置` 中的 values 与预期一致，Release 状态恢复正常。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 上传返回 409 `chart X version Y already exists` | 同名同版本已存在 | 提升 `Chart.yaml` 的 version 后重新打包上传 |
| 上传返回 409 `identical chart package already exists` | 包内容与历史版本完全相同 | 实际修改 Chart 内容（只改版本号无效）后重新打包 |
| 上传返回 413 | 超过 `appstore.max_upload_mb` 上限 | 精简包体积，或由管理员调整该配置的部署取值 |
| 上传返回 400 `chart type "library" is not installable` | Chart 为 library 类型，不可安装 | 将 `Chart.yaml` 的 `type` 改为 `application` 或删除该字段 |
| 安装报 chart dependencies 相关错误 | 子 chart 未打入包内 `charts/` | 执行 `helm dependency build` 后重新打包 |
| 安装后 Pod 处于 `ImagePullBackOff` | 镜像未推送到目标集群可达的镜像仓库 | 推送镜像，或调整 values 中的镜像地址为其可达仓库 |
| 普通用户看不到「上架应用」按钮 | 上架需要 root/admin 权限 | 使用管理员账号上架 |
| 普通用户安装被拒绝 | 普通用户仅可安装到属于自己的命名空间 | 改用自己的命名空间，或联系管理员 |

## 备注

- 本文面向应用商店使用者。Chart 的上架与打包规范（`helm package`、macOS `._*` 文件清理等）见官方 Chart 仓库的 `docs/appstore-chart-guide.md`。
- 应用商店仅接受 `.tgz` 上传导入，不提供 Chart 仓库 URL 直连导入。
- 配置项 `appstore.max_upload_mb` 的默认值为 32MB，实际取值视部署环境而定。
