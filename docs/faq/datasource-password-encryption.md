# FAQ-005 数据源密码加密与密钥轮换

- **分类**：数据源与安全
- **涉及组件**：数据源、`config.yaml`

## 现象

历史版本中，数据源配置会以 JSON 原样保存到数据库，日志、告警、Redis、MySQL 和 PostgreSQL 等数据源的密码字段可能以明文形式存在。数据库备份、误导出或越权访问时，密码存在泄露风险。

## 根因

原有实现未对数据源密码字段进行加密处理。启用本功能后，数据源密码使用 `config.yaml` 中的密钥加密保存；服务在连接、Ping、代理登录和告警查询时仅在内存中解密使用。

## 验证方式

1. 检查 `config.yaml` 的 `default` 下已配置 `encryption_key`。
2. 新增或编辑并保存一个数据源，检查数据库中密码字段是否以 `ENC:v1:` 开头。
3. 使用连接测试、Ping、代理登录或实际查询验证数据源可正常使用。

## 解决方案

### 首次启用

在 `config.yaml` 中配置密钥并重启服务：

```yaml
default:
  # 数据源密码加密密钥，必填，不允许关闭，使用 32 字节随机密钥
  encryption_key: "<base64 编码的 32 字节随机密钥>"
```

已有明文密码不会自动迁移。进入数据源编辑页后直接保存，无需重新填写密码，后端会将原密码转换为密文。

### 更换密钥

1. 备份数据库和原 `config.yaml`。
2. 配置新密钥，并将原密钥临时配置为 `encryption_key_old`。
3. 重启服务。
4. 逐个编辑并保存已有数据源，无需重新输入密码。
5. 验证数据源连接、Ping、代理登录或查询功能。
6. 确认全部数据源均已重新保存后，删除 `encryption_key_old` 并重启服务。

```yaml
default:
  encryption_key: "<新密钥>"
  # 密钥轮换期间临时填写旧密钥，完成数据源重新保存后删除。
  encryption_key_old: "<旧密钥>"
```

## 备注 / 风险

- 未配置 `encryption_key` 时服务不会启动。
- 更换密钥后未配置 `encryption_key_old`，旧密文无法解密。
- 删除 `encryption_key_old` 前，必须确认所有数据源已使用新密钥重新保存。
- 当前不提供自动批量重加密，需要通过页面逐个保存已有数据源。
- 本功能覆盖日志、告警、Redis、MySQL 和 PostgreSQL 数据源密码；不包含邮件 SMTP、Helm 仓库及其他业务凭据。
